本地小批量日常流程

首次：读取最近 100 条真实收藏 → 只建立基线 → 结束，零下载。

日常：补清理 → 从顶部扫描到可靠旧边界 → 新增全部记账 → 待办按阶段续跑 → 批次收尾删合格视频。

每天累计最多 50 条；超过 600 秒跳过；本地媒体 1 GiB 上限；剩余低于 10 GiB 暂停。所有外接盘交互已关闭。

真实 1 条全链路通过；正式数据清空与定时部署尚未执行。阅读完整改造与验证报告

03 /

把每个阶段再展开一层

下面描述三个独立入口的内部顺序。日常 run 复用单条处理函数，维护操作则在整批末尾统一执行。

01采集：收藏列表 → 视频sync.mjs
  • 扫码登录保存在专用 Chrome profile；扫描器读取收藏分页响应，提取视频信息和签名播放地址。
  • 按账本筛 pending，避免“视频清理了，又被每日扫描重新下载”。图集、超长、无地址分别跳过；地址过期等待重新扫描。
  • 新下载校验大小、MIME、音轨，支持 CDN 和音轨档位回落。缓存跳过不等于 HTTP 字节续传。
  • sync 收到整批下载结果后写账本；run 则每次只交给下载器一条，单条结束后写库。
02转写：视频 → 可复用文字extract.mjs
  • 抽成 16 kHz 单声道 MP3；超过 290 秒时按静音切片，按片调用云端 ASR。
  • 纯文字与逐词时间戳分开存；时间戳只有模型返回时才生成。0 字也记为有效转写，再交由提炼阶段判断材料。
  • 独立 extract 在转写前归档历史素材，因此本轮新转写的视频通常等下次 extract 才归档；run 在当轮整批结束时归档。
  • 临时音频会清理，但“临时音频小”不代表下载的 mp4 总量受到控制。
03提炼：文字 → 知识笔记notes.mjs
  • 默认少于 50 字直接待 OCR；其他文字由 LLM 判断够不够成稿。内容缺一部分时也可以成稿并保留 needs_ocr 标记。
  • Markdown 包含分类、时效、标签、三个日期、视频 ID 与来源链接。收藏日期缺失时回退到首次扫描日。
  • 正式入库记录 prompt_hash，默认沿用原文件名。--rename 允许新名字，但不会自动清理旧文件。
  • 试跑只写文件不改条目账本。程序校验 JSON 和非空正文，不能替代对内容忠实度的人工验收。
04 /

状态是进度，不是文件存在性

正常路径只有四步，另外三种状态记录跳过、失败和取消收藏。媒体清理使用单独的 media_deleted 标记，不会让已完成条目自动回到待下载。

pending · 待下载

由扫描新增。普通下载路径只选这种状态；新鲜播放地址来自本轮扫描，不长期写入账本。

下一步：下载 → downloaded，或按内容规则 skipped。

对账只处理收藏关系

全量扫描才允许对账，默认拟移除比例超过 10% 就拒绝。removed 只改状态，不删除产物；重新看到也不会自动恢复。

恢复需要看失败阶段

请求层有退避重试，条目层有 attempts。人工 requeue 目前统一回 pending，不能当作“自动找到断点”的按钮。

05 /

文件在哪里，哪些会移动或删除

原视频体积最大；文字、笔记和账本较小。要适应小磁盘，关键是限制工作视频，而不是压缩文字。

视频归档 = 搬走

复制整个目录，核对文件数与字节数，删除源目录，再更新账本路径。不是内容哈希校验，也不是跨盘原子事务。

文字备份 = 保留副本

本地保留供提炼使用，外接盘多留一份；源文件删除不跟删，按大小跳过或覆盖。不是历史版本备份。

7 天规则不是容量上限

待转写、失败、待 OCR 条目不被它统一清理；外接盘长期不在时，符合条件的视频仍可能到期删除。

2026-09-12 磁盘快照：内置盘剩余约 29 GiB，工作视频约 138 MiB，T7 未挂载。

全量初始化实际仍指向本地 [F5]；5 GiB 阈值只是运行后的告警 [F6]。当前不能靠配置承诺“始终保留空间”。

建议改进 · 尚未实现

全量直接写入确认挂载的外接盘；本机保留文字与小缓存。下载前和运行中检查空间，可先按保留 15 GiB 空闲、缓存约 2 GiB 设计停止条件。外接盘不在时，继续处理文字、暂停新增媒体。

06 /

运行骨架：谁能启动，结果去哪里

锁、日志、配置和告警由公共模块支撑；它们帮助追踪运行，但不等于全部异常和恢复路径已经闭合。

配置与互斥

配置来自命令行、环境变量、~/.dustoff/dustoff.conf 和默认值。支持初始化专用的 _INIT 键；sync 仍有独立解析器。

各独立阶段用各自 PID 锁，run 同时取四把锁。SQLite WAL 支持读写衔接，避免重复付费仍需依靠程序互斥。

运行现场

runs/<时间戳>-<阶段>/ 保存日志、结果及部分中间清单，默认保留 30 天。失效登录写 NEEDS_LOGIN。

零散失败可能以退出码 0 结束；不能仅以 0 判断每条全部成功。试跑、预览与正式运行的落盘和锁行为也不同。

用途入口 / 参数实际边界
日常增量run.mjs --limit 5最多处理 5 个候选；当前仍需注意积压遗漏。
消化已有产物run.mjs --no-scan选 downloaded / transcribed；pending 无新鲜地址，不处理。
只做到转写run.mjs --skip-notes不调用提炼，但仍处理媒体维护。
笔记试跑notes.mjs --out <目录>写试跑文件，不改条目账本。
更新旧版笔记notes.mjs --stale只查正式 extracted 中提示词不同的条目。
复用旧扫描sync.mjs --resume <run-id>继续下载，前提是旧签名地址仍有效。
全量初始化sync.mjs --init先修正有效落盘位置与空间保护 [F5 / F6]。
强制重转extract.mjs --force目前选择 transcribed 重转；不是通用 failed 重试 [F4]。

退出码：0 正常结束（可有单条失败） · 1 错误 / 中止 · 3 已在运行 · 4 登录失效 · 5 磁盘不可用 · 6 配置问题。上表用于理解，不会执行任何命令。

07 /

图中的六个缺口，与启动顺序

这些问题不改变三段架构，但影响恢复、付费次数和磁盘占用。下列标记在时序与存储图中使用同一编号。

F1

日常入口漏掉中间状态积压

默认扫描只选 pending。下载或转写后中断的条目，普通 run 不会自动续跑。

run.mjs · pendingAmong

F2

下载失败重复累计次数

run 导入下载失败时加一次，主循环再加一次；两轮失败就可能达到默认放弃条件。

run.mjs / scripts/ledger.mjs

F3

待 OCR 媒体漏出归档范围

提炼缺料进入 skipped 后，不再被媒体归档或过期清理选中，可能长期滞留本地。

scripts/ledger.mjs · archivable / cleanable

F4

强制转写参数与文档语义不同

extract --force 实际选已转写条目重转，不是重试 failed，可能造成重复转写费用。

extract.mjs · FORCE 选择分支

F5

初始化仍可能落内置盘

本机未配置 DUST_MEDIA_INIT；普通 DUST_MEDIA 优先于外接盘默认值。当前 --init 实际仍下载到本地。

sync.mjs · 配置优先级

F6

空间告警不能限制下载

sync/run 在收尾告警；没有下载硬停止和缓存总量上限。run 也不是每条完成即归档。

sync.mjs / run.mjs · 磁盘维护

现在就能做

  1. 用已有文字试写 3–5 篇。 不用先下载全部收藏。
  2. 检查内容忠实度与回源。 薄材料允许短笔记，不强求所有章节。
  3. 核实配置与备份。 Key 填写不等于有效；文字自动备份也不包含账本。

扩大运行之前

  1. 全量前处理 F5 / F6。 外接盘挂载、初始化目录与空间停止条件。
  2. 自动化前修 F1–F4。 再人工监督跑 5–10 条，核对重复运行和归档。
  3. 数轮稳定后再接定时。 不必等 OCR、图集和知识图谱全做完。
