# 下载前用途分流：实现与验证

## 本次结果

在原来的扫描、下载、ASR、笔记链路中增加下载前用途判断。用途模型使用本机 OpenAI 兼容网关，模型别名 `glm`，独立配置 `DUST_ROUTER_BASE`、`DUST_ROUTER_KEY`、`DUST_ROUTER_MODEL`。ASR 和笔记模型保持原配置。

输入仅包含标题（含话题）、作者、时长和媒体类型；不发送视频、下载地址、登录态或其他条目的内容。提示词明确将元数据视为内容，不执行标题中的指令。输出限定为用途和简短理由，没有丢弃收藏选项。模型判断持久化到账本，重试不会重复分类，手动设置优先。

| 用途 | 下载与处理 | 保存规则 |
| --- | --- | --- |
| 保存视频 `video` | 优先高清带音轨，完成为 `saved`；不调用 ASR/笔记 | 长期保留视频与来源信息 |
| 口播知识 `speech` | 低画质带音轨 → ASR → 笔记 | 可靠文字落盘且没有待 OCR 标记时，可清理临时视频 |
| 画面知识 `visual` | 高清带音轨 → ASR → 笔记，保留待 OCR 标记 | 保留清晰素材，尚未接入 OCR 引擎 |
| 视频和笔记 `both` | 用户手动选择；高清 → ASR → 笔记 | 同时保留视频和文字 |
| 待确认 `review` | 暂不下载、不丢弃；退出自动待办 | 由用户在详情选择用途后恢复 |

高清规格按分辨率优先、同分辨率较高码率选择。优先档下载或音轨验证失败时，可回落平台默认播放档，不能保证作者上传原件。低画质仅降低视频规格，仍验证音轨。下载端记录实际使用的档位和宽高，来源侧文件不保存签名地址。

## 存储与恢复

- 视频保留目录默认为 `~/.dustoff/saved-media`，与临时缓存、临时音频目录不能重叠；所有写入仍禁用外接盘路径。
- 收藏目录默认独立上限 1 GiB，设置页可修改。满额暂停新增处理，不自动删除收藏。临时缓存仍最多 1 GiB，本机至少保留 10 GiB 空闲。
- 下载通过逐块容量检查和临时文件验证后替换，缓存附带规格记录，低画质不会被当作高清成果。
- 收藏用途、双份保留、画面知识及已知待 OCR 素材都排除在自动清理之外。
- 网关 HTTP 错误、超时或 JSON 无效进入原有重试规则；不悄悄按低画质下载，也不标为跳过。三次失败后可从控制台恢复。
- 人工覆盖使用共享流水线锁，仅允许当前启用范围内的作品；基线、图集、超时长和已移除作品不通过这个入口重新入队。已存的文件不主动删除。
- 改用途后恢复按新用途检查素材规格：保存视频不能因存在旧转写稿而直接进入笔记阶段；高清保留分支须先获得符合规格的媒体。

## 控制台

作品详情新增“收藏用途”，显示模型建议/手动选择及理由；可选择保存视频、口播知识、画面知识、视频和笔记、待确认。保存后在下一轮运行处理，不立即下载。已有本地视频可直接打开。

账本增加“视频已保存”“待确认用途”筛选，总览提示待确认数量，日志汇总保存视频与待确认数量。设置增加用途模型参数、视频收藏目录和独立容量上限。密钥不回显，空白提交保留原值；允许本机 HTTP 网关地址，远程地址仍要求 HTTPS。

本次配置已写入用户私有配置文件，权限为 600，仓库示例只保留空密钥。旧条目没有自动重分类或重下载，若要补存已有条目，可在详情修改用途。

- 完整测试：`node --test tests/*.test.mjs`，39 项中 37 通过、0 失败，2 项原有真实 launchd 测试按默认条件跳过。
- 最后补充用途切换后的重试边界，再运行 `tests/routing.test.mjs` 和 `tests/console.test.mjs`，15 项全部通过。
- 隔离模拟网关与实际 ffmpeg/ffprobe 短视频下载验证：保存分支不调用 ASR；口播低档、画面高清；待确认不下载；重复运行不重复调用模型；清理保留视频/画面素材；容量中途超限移除半成品；网关故障保留待办；手动修改不占每日额度。
- 五条真实账本标题通过用户网关实测：三条宋雨琦现场内容均为 `video`，两条开源工具介绍均为 `speech`。分别耗时约 1.39、1.10、1.26、4.96、0.96 秒。真实请求只试判标题，不改账本或下载这些作品。
- 网关实测发现 `glm` 不接受关闭思考，已使用支持的 `reasoning_effort=low`。
- 本机账本在共享锁下备份到私有 `~/.dustoff/backups/before-routing-*.sqlite` 后迁移；比较迁移前后的全部旧字段，122 条记录完全一致。
- 已在业务空闲时重启本机控制台，浏览器核对模型设置、密钥隐藏、新状态筛选和用途表单布局。没有修改定时安排。

本次未重新下载真实抖音作品，媒体端到端验证使用本地模拟下载源与真实编码视频。真实平台可用档位、标题判断的长期准确率仍以之后日常运行结果为准。
