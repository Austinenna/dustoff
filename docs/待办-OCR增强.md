# 待办：OCR 增强（暂缓）

> 记录于 2026-09-01。当前 0.3 只用 ASR，这份是把 OCR 加回来时的完整依据。

## 为什么暂缓

先只用 ASR，链路简单：下载 → 抽音频 → ASR → 提炼。不需要抽帧、不需要 OCR 引擎、
不需要文本合并去重、不需要质量分支判断。先把端到端跑通再谈增强。

## 为什么迟早要加回来

**ASR 拿不到屏幕上的文字。** 实测一条 25 秒的屏幕录制视频：

```
ASR  拿到  171 字   ← 口播内容
OCR  拿到 9396 字   ← 屏幕上的所有文字
```

ASR 只说了「它就从 39 种图表里选结构」，而 OCR 把那 39 种逐个列了出来：
Sankey / Fishbone / Wardley map / Kanban / User journey / Gantt / Flowchart /
Timeline / Venn / Treemap / Quadrant / Swimlane / Radar…

对「屏幕录制 / PPT / 教程」类内容，丢掉 OCR 等于丢掉绝大部分信息量。

## 加回来时的三个已验证结论

### ① OCR 的职责变了：不再是捞字幕

原本要密集抽帧是为了不漏字幕。但硬字幕的内容 = 口播内容，ASR 已经覆盖。
实测那条视频，逐帧 OCR 的 467 个片段里**只有 35 个是字幕**，432 个是屏幕文字。

所以 OCR 的唯一职责是：**捞屏幕上那些不在语音里的东西**。

### ② 关键帧不够，会漏 73%

剔除字幕后再比：

```
逐帧捞到屏幕文字  432 个
关键帧捞到         87 个
漏掉              185 个 → 73%
```

漏的正是最值钱的（Timeline / Quadrant / Radar / Swimlane / Loop flywheel / Nested…）。
原因是屏幕录制的内容**连续滚动**，25 秒里只有 5 个场景切变，但滚过了十几屏。
场景检测天生抓不住渐变。

### ③ 但也不该一律逐帧：密度差 130 倍

```
              屏幕文字量    逐帧耗时   关键帧耗时
纯口播  31s        105 字      13.6s      2.5s
调色教程 86s       701 字      40.3s      7.5s
屏幕录制 25s      8930 字      15.3s      5.5s
PPT口播 156s     13890 字      78.9s     13.3s
```

纯口播那条逐帧跑 13.6 秒只换来 105 个字——真人出镜、屏幕上本来就没东西，纯浪费。

## 加回来时的方案：5 帧探测分流

均匀抽 5 帧快速 OCR，按字数决定走哪条路。实测分界很干净：

```
纯口播      90 字  ┐
调色教程   253 字  ┘ 低
                 ─── 阈值 ~500 ───
PPT口播   1199 字  ┐
屏幕录制  2228 字  ┘ 高
```

探测本身只花 4-10 秒。

```
ASR（云端）──────────────────→ 口播全文
抽 5 帧探测密度
  ├─ < 500 字 → 关键帧 OCR（几张）
  └─ ≥ 500 字 → 逐帧 OCR
        ↓
两路文本 + 12 张关键帧 → 一次多模态调用 → 笔记
```

## 实现要点

- **OCR 引擎用 macOS Vision**（`swiftc` 编译一个 20 行的 `ocr.swift`，
  `VNRecognizeTextRequest` + `recognitionLanguages = ["zh-Hans","en-US"]`，
  置信度低于 0.4 的丢掉）。实测 3.0× 实时，中文准确度很好，零成本。
  跨平台时这一块要换（Linux 上没有 Vision，得用 PaddleOCR / RapidOCR）。
- **相邻帧去重**：字幕逐帧重复，需要合并。简单的「与前一条互为子串则合并取长者」
  就能把 467 行压到可用规模。
- **12 张关键帧要单独抽并长期保留**，那是给多模态看的视觉资产，跟 OCR 是两回事。
  白板推导、代码截图、图表——图本身比 OCR 出来的文字更有价值，而且只占约 1 MB。
- 关键帧选取可参考场景切变 + 感知哈希去重 + 质量打分，注意避开转场帧和黑帧
  （切变点后延迟一点取帧；首尾取中点而非端点）。

## 还没测的

**「屏幕文字密集」的条目在收藏里占多少。** 四条样本里是 2:2，样本太小。
等 ASR 链路跑起来、积累几十条之后再测——如果大部分是纯口播，
那逐帧那条路很少触发，加 OCR 的总成本比现在估的还低。
