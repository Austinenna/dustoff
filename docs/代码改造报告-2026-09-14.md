## 改造后的流程

```text
启动并取得共享锁
  ├─ 没有基线 → 读取最近 100 条真实收藏 → 保存基线 → 结束（零下载）
  └─ 已有基线 → 补清理上次遗留的合格视频
                → 从顶部扫描，确认旧边界；未确认继续分页
                → 新增与扫描边界一起提交到 SQLite
                → 从持久待办按等待顺序处理
                    每天累计最多 50 个不同条目
                    下载前核实时长、空间；必要时单独刷新播放地址
                    下载 → ASR → 笔记，各阶段完成后立即记账
                → 批次收尾删除可靠非空转写对应的视频
                → 保存摘要、失败原因与剩余待办，释放锁
```

## 已修改的内容

| 范围 | 实现结果 |
|---|---|
| 基线与增量 | 首次自动只建 100 条基线。日常初始窗口不超过 100，支持继续分页；使用最多 100 个保存参照，通常需 3 个按原顺序出现的连续参照确认边界 |
| 真实分页 | 兼容请求 URL 与 POST 请求体中的 cursor；按请求/响应游标连成完整页链，拒绝跳过缺失页。分页失败或边界不明不推进账本 |
| 原子记账 | 基线、新增待办和扫描边界在同一 SQLite 事务内提交。未知历史不会因单独导入元数据自动进入本次日常队列 |
| 持久待办 | 不再依赖“本轮是否再次扫到”。pending、downloaded、transcribed 按阶段续跑；已完成项不再进入队列；旧地址可按作品 ID 单独刷新 |
| 每日额度 | 按本机自然日记录参与处理的不同作品 ID；同日重启或换入口不重置额度，同一条跨阶段续跑不重复占名额。单轮可用 `--limit 1` 控制真实验收规模 |
| 失败恢复 | 下载失败只计一次；单阶段最多 3 次失败后停止自动处理。`run.mjs --retry ID --no-scan --limit 1` 或账本的单条 requeue 按现存产物恢复，不一律退回下载 |
| 时长 | 元数据超过 600 秒主动跳过；未知时长先刷新，仍未知不下载。下载后还用 ffprobe 校验实际时长与音轨 |
| 磁盘 | 1 GiB 本地媒体累计预算，10 GiB 最低剩余空间；临时媒体纳入统计。视频、音频及切片均流式写入，每块写前核实实际预算，不仅依赖 Content-Length |
| 成果保存 | 文字和笔记先写临时文件、同步并重命名。视频先写 `.part`，校验后才成为正式文件；中断半成品不会被当作下载成功 |
| 收尾清理 | 保留期改为 0，在批次收尾执行，下次启动补清理。依据 ASR 完成记录和真实非空文字文件，不受后续笔记失败、缺料或最终 status 限制。删除失败不会触发重新 ASR |
| 外接盘 | 视频归档、文字备份、挂载检查全部停用。`/Volumes` 路径及指向它的链接被拒绝，旧配置或插入 T7 都不会自动恢复；旧归档功能代码保留但不会执行 |
| 运行保护 | 所有正式处理入口共用一个锁；请求默认 180 秒、整轮默认 2 小时，子进程另有限时。运行记录按保留天数清理，并限制每入口最多 100 份 |

新模块是 `scripts/policy.mjs`（策略与容量）、`scripts/daily.mjs`（基线、队列、额度）、`scripts/incremental.mjs`（分页链与边界）。没有引入 npm 依赖、服务或新的调度平台。

## 入口变化

- `node run.mjs`：正式日常入口，首次自动建基线。
- `node run.mjs --limit 1`：最多实际处理 1 条；首次仍只建基线。
- `node run.mjs --no-scan --limit 1`：从已经登记的待办继续，必要时刷新待下载作品的地址。
- `node run.mjs --dry-run`：查看本地基线/队列计划，不进行网络采集或模型调用。
- `node run.mjs --status`：查看基线、队列数量、今日额度及生效策略。
- `node sync.mjs`：复用同一个日常编排，只下载；仍受基线和额度约束。
- `node extract.mjs` / `node notes.mjs`：只处理本次启用范围内的条目，共享每日额度与互斥。
- 旧全量 `--init`、旧批次 `--resume`、独立批量 `scripts/download.mjs` CLI、旧 Whisper `scripts/fetch.mjs` 入口暂停，防止绕过当前约束。独立 ASR 的 `--force` 暂停。

这些是有意的兼容性变化：不要继续照旧版全量/外接归档命令操作。恢复外接功能需后续明确改动，当前没有一个旧配置项能将它自动打开。

## 验证边界

本轮没有人为取消收藏、故意断网、终止付费请求或填满磁盘来制造所有故障；边界参照大批消失、跨自然日长期运行、模型超时和崩溃恢复未全部做现场故障演练。相关保护已经实现，报告不将代码检查等同于所有场景实测。

1 GiB 只指媒体和临时媒体，账本、笔记、文字、浏览器 profile 另有实际占用。零字转写和失败视频保留，累积触限时会暂停，不能保证无期限每日都有新下载。源视频删除后，未来 OCR 或重新 ASR 需要重新获取原片。

## 正式启用前仍需完成

1. 停止运行并核对清理清单，清空本地旧业务账本与产物，保留配置、Key 和登录态；外接盘旧数据清理暂缓。
2. 核对正式路径与实际生效参数。代码会限制旧宽松值，例如原来 200 条扫描上限收紧到 100、5 GiB 空闲门槛提升为 10 GiB。
3. 在正式环境运行一次，只建立新的 100 条基线；这将成为真正的新增起点。隔离验证中的历史基线不会复制到正式账本。
4. 由用户查看真实样本笔记；需要时用正式基线之后 1–3 条新增再验收。
5. 确定每天几点，安装并实际验证 launchd，明确睡眠、关机和错过触发时的行为。本轮未安装定时任务。
