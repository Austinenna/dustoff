## 实现和操作

新增 `scripts/schedule.mjs`：提供 `start [HH:MM]`、`time HH:MM`、`status`、`stop`。配置文件为 `/Users/enna/.dustoff/scheduler/daily.plist`，仅手动 bootstrap 到当前用户的 GUI 会话，没有安装进 `~/Library/LaunchAgents`、`/Library/LaunchAgents` 或 `LaunchDaemons`。注销或重启后任务消失，时间配置保留。

启用时检查程序路径、验证 plist；非法时间不影响原任务，更新失败恢复旧定义。重复开启相同配置不会重复加载。修改已开启的定时会重新加载日历；修改已关闭的定时只保存时间。若定时批次正在执行，拒绝停止/重载，提示等本轮完成。

新增 `scripts/scheduled-run.mjs`：定时到点后调用现有 `run.mjs`，固定项目目录、Node 绝对路径和工具 PATH，继续读取现有 `dustoff.conf`。不把 API Key 或登录信息复制到定时配置。

日常新增扫描、基线、共享锁、每日最多 50 条、单条最多 10 分钟、媒体 1 GiB/空闲 10 GiB 限制、外接盘停用、收尾视频清理及转写稿完整性校验全部沿用现有入口。

定时封装只保留最新日志 `~/.dustoff/scheduler/latest-run.log`（覆盖写入，最多 1 MiB），及一份 `last-run.json`。正常业务记录仍在 `~/.dustoff/runs`，沿用 30 天/每入口最多 100 份的限制。

常用命令（先进入 `/Users/enna/Projects/apps/dustoff`）：

```sh
node scripts/schedule.mjs status
node scripts/schedule.mjs time 21:30
node scripts/schedule.mjs stop
node scripts/schedule.mjs start
```

`start` 不会立即运行下载；要立即跑一轮仍使用 `node run.mjs`。重启或注销后再次执行 `start` 即可恢复保存的日程。

## 日常注意

关闭终端或退出 Codex 不影响已加载任务。电脑本地时区改变后，22:00 随系统本地时间。登录失效、网络故障或磁盘空间不足仍需按业务日志处理；定时器不会绕过这些条件。Node 或项目路径改变时，以当前可用 Node 再执行 `start` 更新定时配置。

转写稿和现有业务代码的先前未提交修改保留；本次未自动提交 Git。详细日常操作见[日常使用指南](日常使用指南.md)。
