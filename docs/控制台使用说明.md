# dustoff 本机控制台

2026-09-14 实现。采用已确认的 A 版留白设计，接入现有日常流水线、SQLite 账本、笔记目录和 macOS 每日定时。无需安装 npm 依赖。

## 打开

在 Finder 中进入项目，双击 `打开控制台.command`。它会启动后台服务并打开浏览器；重复打开会复用同一服务。默认地址为 <http://127.0.0.1:47831>，只能在这台电脑访问。

也可在项目根目录执行：

```sh
node scripts/open-console.mjs
```

关闭网页不会中断手动处理，也不会关闭每日定时。重启电脑后，重新双击文件即可打开控制台。Node 需支持内置 `node:sqlite`；本机已用 Node 24 验证。

## 七个页面

| 页面 | 可以做什么 |
|---|---|
| 总览 | 今日成稿、累计笔记、待办、每日额度、磁盘占用、下一次定时、最近笔记 |
| 运行与定时 | 改起始时间与重复间隔、开启或关闭定时、选择登录后自动启用；手动运行、设置本轮数量、只继续已有待办、停止本控制台启动的本轮 |
| 作品账本 | 按标题、作者、ID 搜索，按状态筛选，每页 20 条；查看完整数据库字段、产物路径和错误；将失败作品恢复为待办 |
| 结果浏览 | 每页 6 条，搜索与「有笔记／仅文字稿」筛选；左侧选作品、右侧阅读；切换知识笔记和原始 TXT，打开 Obsidian、所在文件夹或原作品 |
| 运行日志 | 业务批次、定时启动、控制台操作三类日志；查看批次结果 JSON，筛选错误行；页面可见时每 5 秒刷新 |
| 登录管理 | 剩余有效时间、预计到期、最近检查、在线验证；直接打开 Chrome 官方登录页、取消登录任务 |
| 设置 | 处理限制、超时、日志保留天数、登录预警天数、模型、密钥、输出目录与转写热词 |

结果列表优先显示笔记元信息中的标题，标题最多占两行，悬停可看全。搜索匹配原作品标题、作者、ID，也匹配笔记文件名；没有全文检索。窄窗口下先展示作品列表，选中后进入正文，可返回列表。

账本是只读浏览，没有任意 SQL 修改或批量删除入口。失败恢复根据已有产物回到合适阶段，保留当日额度；它只恢复待办，不立即调用模型。确认恢复成功后，再手动开始一轮或等待每日定时。

## 定时和手动运行的关系

按设定的起始时间与小时间隔，由 macOS 的 launchd 调用定时入口，确认到期后启动 `run.mjs`，控制台用于查看和修改安排。因此网页不需要一直打开，电脑需保持登录并有网络；休眠时不会主动唤醒电脑。

- 当前目标安排为起始 22:00、每 12 小时一次，即 22:00 和次日 10:00；登录后自动启用沿用原设置。
- 「保存安排」在定时已开启时更新当前任务；已关闭时只保存起始时间、间隔和登录自动启用选项，当前会话要立即恢复安排还需点「开启定时」。
- 勾选「登录后自动启用定时」并保存，会写入当前用户的 LaunchAgents，后续登录恢复定时安排，不会登录就立即处理一轮。
- 「关闭定时」同时取消当前安排和后续登录自动启用。定时批次正在处理时，要等其结束后再改安排。
- 手动和定时共用 `.lock.pipeline` 与每日额度，同一时间只处理一轮。控制台只提供停止自己启动的任务；其他终端或定时启动的任务可以查看进度。

## 设置如何生效

配置写入 `~/.dustoff/dustoff.conf`，下一次启动的处理使用新值。输出目录修改只影响新文件，不搬迁旧结果；账本继续指向旧文件。

已有密钥不回显，留空保留旧值。环境变量覆盖的字段显示为只读；多个页面或手工编辑发生冲突时，保存会要求刷新，避免覆盖新配置。

本版沿用已确定的日常模式限制：最多 50 条/日、每条 10 分钟、媒体缓存最多 1 GiB、空闲空间至少 10 GiB。控制台允许在这些范围内调整，显示实际生效值。外接盘功能仍停用。

## 登录管理（2026-09-15）

总览显示登录摘要，进入「登录管理」可以查看预计到期时间和剩余天数。「立即检查」读取 dustoff 专用 Chrome 资料，并访问抖音个人页核实状态，不采集收藏、不调用模型。每日正常运行继续更新登录到期记录；预警天数可在设置中调整，默认 7 天。

到期时间来自登录 Cookie，是估算值，抖音可能提前使会话失效；「在线验证」单独显示是否实际确认可用。无法判断时显示未确认，不把剩余天数当成保证。

点击「扫码登录」后，立即启动专用 Chrome 并打开抖音官方页面，不先尝试后台取码，也没有 30 秒等待。用手机抖音扫描 Chrome 页面中的二维码，核对并确认电脑登录。二维码刷新、协议阅读及额外验证直接在官方页面完成。控制台只显示简短进度，取消后隐藏进度提示，不保留二维码展示区。

收到新凭据后，自动保存到 dustoff 专用资料并更新到期记录。登录使用临时资料，导入失败尝试恢复原凭据；取消或 5 分钟超时会关闭临时 Chrome 并清理临时资料。Cookie 不回传给控制台网页，也不提交到 Git。

登录、检查和日常处理共用运行锁；有一项正在执行时，需要等它结束。关闭控制台网页不会立即取消扫码任务；可先点「取消本次操作」，否则任务到时自动结束。

## 日志与维护

业务日志在 `~/.dustoff/runs/`，定时入口日志在 `~/.dustoff/scheduler/`；新增的控制台服务日志为 `~/.dustoff/console/service.log`，操作输出为 `latest-action.log`，最后一次操作结果为 `last-action.json`。页面展示日志末尾最多 128 KiB，操作日志轮转限制约 1 MiB。业务日志按设置中的天数清理，同时受原有每入口最多 100 份限制。

控制台只监听 `127.0.0.1`，写操作校验页面来源和令牌；日志展示遮蔽已配置密钥。笔记阅读器不执行原始 HTML、不加载外部图片，常用 Markdown 结构可以阅读；完整 Markdown 编辑仍使用 Obsidian。单份文件超过 4 MiB 时使用本机阅读器打开。

开发时可在前台运行 `node console.mjs --port 47832`，按 Ctrl+C 关闭该前台服务。后台启动器支持 `--no-open`，便于只启动服务；用 `DUST_CONSOLE_PORT=47832 node scripts/open-console.mjs` 可更换端口。

### 起始时间与间隔（2026-09-15）

「运行与定时」支持起始时间 HH:MM 与运行间隔（1–720 整数小时）。修改任一项后，从下一次起始时刻开始，之后沿固定时间轴重复；例如 22:00＋12 小时为 22:00、次日 10:00、次日 22:00。间隔不是从上一轮完成时算起。只保存相同值或修改登录自动启用选项，不重置已有时间轴。

关闭后重新开启，从下一次起始时刻重新安排，不补跑停用期间任务。休眠期间错过多轮时最多补一次；上一轮执行期间跨过的时刻不在结束后追赶，仍等下一次安排。同一计划时刻只记一次启动，手动运行不会重置定时安排，日额度继续按自然日累计。

控制台 `POST /api/schedule` 的保存参数为 `action: "save"`、`time`、`intervalHours`、`autoStartAfterReboot`；状态新增 `intervalHours`、`startAt` 与 `nextRun`。旧版每日 plist 自动按 24 小时间隔识别，保存后转换；继续使用原任务标签，避免同时留下两个任务。

CLI 可用 `node scripts/schedule.mjs time 22:00` 改起始时间，`node scripts/schedule.mjs interval 12` 改间隔；状态使用 `node scripts/schedule.mjs status` 查询。关闭状态下修改只保存，开启使用 `node scripts/schedule.mjs start`。
