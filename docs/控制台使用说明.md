# dustoff 本机控制台

2026-09-14 实现。采用已确认的 A 版留白设计，接入现有日常流水线、SQLite 账本、笔记目录和 macOS 每日定时。无需安装 npm 依赖。

## 打开

在 Finder 中进入项目，双击 `打开控制台.command`。它会启动后台服务并打开浏览器；重复打开会复用同一服务。默认地址为 <http://127.0.0.1:47831>，只能在这台电脑访问。

也可在项目根目录执行：

```sh
node scripts/open-console.mjs
```

关闭网页不会中断手动处理，也不会关闭每日定时。重启电脑后，重新双击文件即可打开控制台。Node 需支持内置 `node:sqlite`；本机已用 Node 24 验证。

## 六个页面

| 页面 | 可以做什么 |
|---|---|
| 总览 | 今日成稿、累计笔记、待办、每日额度、磁盘占用、下一次定时、最近笔记 |
| 运行与定时 | 改每日时间、开启或关闭定时、选择登录后自动启用；手动运行、设置本轮数量、只继续已有待办、停止本控制台启动的本轮 |
| 作品账本 | 按标题、作者、ID 搜索，按状态筛选，每页 20 条；查看完整数据库字段、产物路径和错误；将失败作品恢复为待办 |
| 结果浏览 | 每页 6 条，搜索与「有笔记／仅文字稿」筛选；左侧选作品、右侧阅读；切换知识笔记和原始 TXT，打开 Obsidian、所在文件夹或原作品 |
| 运行日志 | 业务批次、定时启动、控制台操作三类日志；查看批次结果 JSON，筛选错误行；页面可见时每 5 秒刷新 |
| 设置 | 处理限制、超时、日志保留天数、模型、密钥、输出目录、扫码登录与转写热词 |

结果列表优先显示笔记元信息中的标题，标题最多占两行，悬停可看全。搜索匹配原作品标题、作者、ID，也匹配笔记文件名；没有全文检索。窄窗口下先展示作品列表，选中后进入正文，可返回列表。

账本是只读浏览，没有任意 SQL 修改或批量删除入口。失败恢复根据已有产物回到合适阶段，保留当日额度；它只恢复待办，不立即调用模型。确认恢复成功后，再手动开始一轮或等待每日定时。

## 定时和手动运行的关系

每天到点由 macOS 的 launchd 启动 `run.mjs`，控制台用于查看和修改安排。因此网页不需要一直打开，电脑需保持登录并有网络；休眠时不会主动唤醒电脑。

- 正式环境保持原来的每日 22:00，登录后自动启用仍未勾选。本次页面验收没有运行正式收藏处理，也没有更改原定时。
- 「保存安排」在定时已开启时更新当前任务；已关闭时只保存时间和登录自动启用选项，当前会话要立即恢复安排还需点「开启定时」。
- 勾选「登录后自动启用定时」并保存，会写入当前用户的 LaunchAgents，后续登录恢复每日安排，不会登录就立即处理一轮。
- 「关闭定时」同时取消当前安排和后续登录自动启用。定时批次正在处理时，要等其结束后再改安排。
- 手动和定时共用 `.lock.pipeline` 与每日额度，同一时间只处理一轮。控制台只提供停止自己启动的任务；其他终端或定时启动的任务可以查看进度。

## 设置如何生效

配置写入 `~/.dustoff/dustoff.conf`，下一次启动的处理使用新值。输出目录修改只影响新文件，不搬迁旧结果；账本继续指向旧文件。

已有密钥不回显，留空保留旧值。环境变量覆盖的字段显示为只读；多个页面或手工编辑发生冲突时，保存会要求刷新，避免覆盖新配置。

本版沿用已确定的日常模式限制：最多 50 条/日、每条 10 分钟、媒体缓存最多 1 GiB、空闲空间至少 10 GiB。控制台允许在这些范围内调整，显示实际生效值。外接盘功能仍停用。

## 日志与维护

业务日志在 `~/.dustoff/runs/`，定时入口日志在 `~/.dustoff/scheduler/`；新增的控制台服务日志为 `~/.dustoff/console/service.log`，操作输出为 `latest-action.log`，最后一次操作结果为 `last-action.json`。页面展示日志末尾最多 128 KiB，操作日志轮转限制约 1 MiB。业务日志按设置中的天数清理，同时受原有每入口最多 100 份限制。

控制台只监听 `127.0.0.1`，写操作校验页面来源和令牌；日志展示遮蔽已配置密钥。笔记阅读器不执行原始 HTML、不加载外部图片，常用 Markdown 结构可以阅读；完整 Markdown 编辑仍使用 Obsidian。单份文件超过 4 MiB 时使用本机阅读器打开。

开发时可在前台运行 `node console.mjs --port 47832`，按 Ctrl+C 关闭该前台服务。后台启动器支持 `--no-open`，便于只启动服务；用 `DUST_CONSOLE_PORT=47832 node scripts/open-console.mjs` 可更换端口。
