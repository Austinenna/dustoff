# 第三段：笔记规格

> 这是**笔记长什么样**的权威定义，第三段的 prompt 从这里生成。
> 前身是 [`旧版-单条链接流程与笔记模板.md`](旧版-单条链接流程与笔记模板.md)——
> 那是一份 whisper 时代的 Claude Skill，靠对话触发、Claude 亲手读写文件。
> 现在整条链路是脚本，输入变成账本里的 `.txt`，输出要机器可解析，
> 所以模板不能照抄，得重写一遍。文末列了具体改了哪些。

## 边界：严格 1 : 1 : 1

```
一条视频  ──→  一份 ASR 转写稿  ──→  一篇笔记
```

不合并、不拆分、不做跨条目关联。去重、找关联、知识图谱都是**再往后一个阶段**的事，
这里一律不碰。判断某个想法该不该进来，只问一句：**它需要读第二条视频吗？**
需要，就不属于第三段。

## 一、谁配写笔记

**收藏夹不等于知识库。** 已转写的 12 条里，一半以上不该进：键帽广告、
合拍段子、河头老街 NPC 台词。没有准入判断就直接提炼，等于给广告认真生成一篇
带标签的 Markdown，还为此付一次 LLM 的钱。

但**光看字数会误判**。实测里最短的一条反而信息密度最高：

```
 337 字  山鬼牺牲流李信     58 秒，句句是干货，笔记写得比 1010 字那条还长
 144 字  键帽广告          纯口播带货，一句有用的没有
```

所以准入分两层：

| 层 | 判断者 | 规则 | 代价 |
|---|---|---|---|
| 硬门槛 | 脚本 | `text_chars < 50` 直接不送 LLM | 免费 |
| 软判断 | LLM | 同一次调用里顺带输出「值不值得收录」 | 已经付过了 |

软判断不额外花钱——反正要把转写稿发过去，让它多回一个布尔值是白送的。
被判定不值的落 `skipped`，`skip_reason` 记明原因，不写笔记文件。

## 二、笔记格式

### frontmatter

```yaml
---
标题: <凝练的主题标题，不抄原标题的标题党写法>
来源: 抖音
作者: <author>
视频ID: <aweme_id>
链接: https://www.douyin.com/video/<aweme_id>
发布日期: <create_time → YYYY-MM-DD>
时长: <duration_s → X分X秒>
收录日期: <生成笔记那天 YYYY-MM-DD>
分类: <一个词，见下>
时效: <none | slow | fast | event>
标签: [<3-6 个关键词>]
---
```

**`分类` 和 `标签` 不重复，是两种东西：**

```
分类   一篇只有一个，回答「这归到哪个架子上」   → 归档，要能批量筛
标签   一篇好几个，等同论文的 keywords         → 检索，要能全文搜
```

**`分类` 暂时让 AI 自由填**，不给固定选项。理由是现有的四个值撑不住——
拿账本里 48 条真实标题试分，最大的桶是「其他」占 38%，而且那里面不是噪音，
是成团的漏类（摄影修图 4、影视娱乐 4、手工艺术 4、硬核工程 3）。
**一个分类体系里最大的桶叫「其他」，说明这个体系是错的。**
48 条只是 5831 条的 0.8%，现在拍板必然还得改。
先自由填，**攒够 200 条看真实分布再锁定列表**——不额外花钱，拿到的是真数据。

> 账本里 `category TEXT` 没有 CHECK 约束，那四个值只写在注释里，
> 数据库本来就什么字符串都收。自由填不需要改 schema。

**`时效` 四档固定**，语义正交，不用改：

| 值 | 含义 | 例 |
|---|---|---|
| `none` | 不过期 | 物理公式、方法论、审美判断 |
| `slow` | 年为单位 | 工具用法、职业建议、行业格局 |
| `fast` | 月为单位 | 软件版本、游戏版本、模型排名 |
| `event` | 绑死某个时间点 | 发布会、活动、节日、新闻 |

### 正文

```markdown
# 核心观点
<2-4 句话讲清这个视频到底说了什么、最有价值的点是什么>

## <分论点小标题>
<结构化要点，可用列表/表格>

## 结论
<视频的落脚点 / 给观众的 takeaway>
```

**长度按信息密度定，不按视频时长定。** 58 秒的阵容攻略可以比 4 分钟的
职业建议写得长，因为前者句句是配置、后者有一半是铺垫。

### 文件名

`YYYY-MM-DD-<简短主题>.md`，日期用**视频发布日**，不是收录日。
落在 `DUST_NOTES`（默认 `~/Documents/抖音收藏`）。

## 三、字段去哪：笔记 vs 账本

判断标准只有一条：**你会不会想在「不打开笔记」的前提下，按这个字段捞出一批？**

| 字段 | 笔记 | 账本 | 为什么 |
|---|:--:|:--:|---|
| `分类` | ✅ | ✅ `category` | 要批量筛，得能 SELECT |
| `时效` | ✅ | ✅ `decay` | 同上：「版本更新了，把 fast 的重跑一遍」 |
| `标签` | ✅ | ❌ | 见下 |
| 笔记路径 | — | ✅ `note_path` | 账本要能找到文件 |

**标签坚决不进账本。** 账本里 47/48 条标题自带作者话题，实测 **127 个不重复标签 / 48 条**，
而且全是同义词碎片：`#ai`／`#AI`／`#人工智能` 是三种写法，
`#王者万象棋`／`#王者万象棋预习班`／`#王者万象棋定档9月`／`#王者万象棋定档9月10日`
是四种写法（后两个纯 SEO）。按这个比例外推到 5831 条是几千个标签，
塞进一列 TEXT 既建不了有效索引也查不准。自由关键词天生该待在 markdown 里，
交给 ripgrep / Obsidian 全文检索——那本来就比 SQLite 干得好。

**双写的一致性：** AI 一次输出，脚本一次写两处（写 md 文件 + `markExtracted()`），
同一步完成，正常不会漂。但你手改笔记里的分类，账本不知道。
原则是**笔记是真相，账本是缓存**；将来加个 `--resync` 从 frontmatter 回灌即可，现在不做。

## 四、提炼指令

给 LLM 的要求：

1. **重组，不复述。** 把口语流水账整理成结构化要点（核心观点／分论点／关键数据／结论），
   不是把转写稿断句排版。
2. **保留有信息量的具体内容**——数字、人名、产品名、金句，这些是笔记的价值所在。
3. **标题的 hashtag 是专名的地面真相。** 转写稿里出现「万象棋」，
   标题里有 `#王者万象棋`，按标题写。热词表覆盖不到的新词全靠这个兜底。

> **已删除：「纠正 whisper 同音／专名错误」。**
> 那条指令是 whisper 时代的补丁——同一条视频、真值取自画面硬字幕，
> whisper 8 个专名全错，qwen 带热词只错 1 个。错误已经在源头（`~/.dustoff/asr-context.txt`）
> 解决掉了，不该再让 LLM 每篇都做一遍无用功。
>
> 注意别把「结合标题 hashtag」这个动作一起删掉——它换了个身份留下来了，见上面第 3 条。

**待定（三篇草稿里是这么处理的，未拍板）：**

- **引流内容**：抖音「干货 + 卖课」的结构极其普遍。草稿的做法是剔掉并脚注说明
  （`> 视频后半段在推销作者的「2026 大模型学习路线图」，属于引流内容，未收录。`）。
  备选：完全不提／原样保留。这个决定影响几千篇。
- **转写稿够不到的信息**：阵容码、仓库地址这类只在画面上的东西，ASR 一个字拿不到。
  草稿的做法是显式警告（`> ⚠️ 视频说会给阵容码，但转写稿里没有——阵容码在画面上`）。
  好处是你知道这篇是残缺的，而且这些标记天然就是 OCR 增强的候选名单；
  坏处是几千篇里会有大量这种脚注。

## 五、相对旧模板改了什么

| 旧版（Skill 时代） | 现在 | 原因 |
|---|---|---|
| Claude 读对话里的链接触发 | 脚本从账本 `claim('transcribed', N)` 批量取 | 不再是 skill，是自动化程序 |
| 输入 = `fetch.mjs` 的 stdout JSON | 输入 = 账本行 + `text_path` 指向的 `.txt` | 第二段已经把产物落盘了 |
| 本地 whisper 转写 | 云端 qwen-audio-3.0 + 热词表 | 见 [`ASR选型-2026-09-02.md`](ASR选型-2026-09-02.md) |
| 「纠正 whisper 专名错误」 | 删除；hashtag 改作专名地面真相 | 源头已解决 |
| 只有自由 `标签` | `分类` + `时效` + `标签` 三层 | 账本的 `category`／`decay` 需要有人填 |
| 无准入判断，来者不拒 | 硬门槛 + LLM 软判断 | 收藏夹不等于知识库 |
| 输出 = Markdown 文件 | 输出 = Markdown 文件 **+** `markExtracted()` 回写账本 | 账本是唯一的跨阶段状态 |
| 存 `~/VideoKB/` | 存 `DUST_NOTES` | 配置化 |
