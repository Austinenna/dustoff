## 1. 日常最常用的操作

**推荐入口：双击项目中的 `打开控制台.command`。** 浏览器打开本机控制台，六个页面分别提供总览、运行与定时、作品账本、结果浏览、运行日志、设置。服务已启动时可直接访问 <http://127.0.0.1:47831>。详细说明见[控制台使用说明](控制台使用说明.md)。

以下保留等价的终端用法。

打开 macOS「终端」，先进入项目目录：

```sh
cd /Users/enna/Projects/apps/dustoff
```

随后按需要选择一条命令执行，不必全部运行：

| 想做什么 | 命令 |
|---|---|
| 手动跑一轮：扫描新增 → 下载 → 转写 → 生成笔记 → 清理视频 | `node run.mjs` |
| 小批量真实运行，本轮最多处理 2 条 | `node run.mjs --limit 2` |
| 快速查看本地待办和今日已用额度 | `node run.mjs --dry-run` |
| 查看账本总览、各状态数量 | `node scripts/ledger.mjs stats` |
| 查看每日定时是否开启 | `node scripts/schedule.mjs status` |
| 开启每日定时，沿用保存的时间 | `node scripts/schedule.mjs start` |
| 把每日时间改为 21:30 | `node scripts/schedule.mjs time 21:30` |
| 关闭每日定时 | `node scripts/schedule.mjs stop` |

`--dry-run` 不扫描收藏、不下载、不调用模型，所以看不到尚未扫描进账本的新收藏。它不能代替真实处理验收。

**你说的“收藏两个 → 手动运行 → 再收藏两个 → 再运行”可以直接这样做。** 等上一轮结束后再次运行同一条命令即可。已完成的条目不会因为再次启动而重做。如果已有旧待办，`--limit 2` 可能先处理旧待办，并不保证只处理刚收藏的两条；这个参数限制本轮处理数量，不是扫描数量。

采用终端用法时，每个新终端窗口先执行一次 `cd`；控制台直接复用相同的日常处理入口。

### 每日定时怎么用

当前设为 **每天 22:00，按电脑本地时区（目前 Asia/Taipei）**。首次启用命令是 `node scripts/schedule.mjs start 22:00`。

- **开启定时**只安排后续每日触发，本身不立即下载。要现在处理一轮，运行 `node run.mjs`。
- **改时间**使用 `time HH:MM`，例如 `time 21:30`，使用 24 小时制。定时已开启时立即更新；已关闭时只保存时间，不擅自开启。
- **重启或注销后**，若未勾选「登录后自动启用定时」，定时不再生效；需要时手动执行 `node scripts/schedule.mjs start`，会沿用上次保存的时间。开启时若今天的时刻已过，下一次是明天该时刻。
- **关闭终端或退出 Codex**不会关闭已加载的定时；需要停止后续定时执行时用 `stop`。若定时批次正在处理，`stop` 和改时间会提示等本轮结束，以免中断作品。
- **休眠错过时间**时，系统在唤醒后补跑一次；不会主动唤醒电脑。关机或注销期间不补跑；登录后自动启用只恢复未来的定时，可自行手动处理一轮。

使用 macOS 自带的 launchd，配置保存在 `/Users/enna/.dustoff/scheduler/daily.plist`，正式环境目前没有放进登录自动加载目录。控制台已提供「登录后自动启用定时」选项；勾选并保存后会写入当前用户的 `~/Library/LaunchAgents/com.dustoff.daily.plist`，重启后登录时自动恢复每日安排。关闭定时会同时移除该自动加载定义。不要直接编辑 plist，用上述命令改时间，以便同步更新系统中实际加载的定义。

`status` 中 `loaded: true` 表示当前已开启，`running: true` 表示定时批次正在处理，`runs` 是本次加载后的触发次数，`lastRun` 是最近一次定时调用的开始、结束及退出码；它们不代表业务全部成功，具体还要看该批次的 `result.json`。

定时入口的最新日志在 `/Users/enna/.dustoff/scheduler/latest-run.log`，每次覆盖，最多占 1 MiB；启动结果在同目录 `last-run.json`。每次正常批次的完整业务记录仍在 `/Users/enna/.dustoff/runs`，按原有保留规则清理。可以用：

```sh
tail -n 60 /Users/enna/.dustoff/scheduler/latest-run.log
```

Node 或项目路径变更后，用当前可用的 Node 再执行 `start` 更新运行路径。使用系统日历触发及唤醒后补跑的行为依据 [Apple 的定时任务说明](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/ScheduledJobs.html)。

```sh

```

2026-09-14 已把正式笔记旁的两份旧 `.md.transcript.json` 迁入程序目录，原稿和笔记逐字节不变。项目内历史验证样本仍保留当时的配套文件，校验命令兼容读取它们；新的日常笔记不会再生成旁置 JSON。

### 视频为什么会消失

视频是临时缓存。**每次批次收尾，包括每次手动运行收尾，都会统一删除符合条件的视频**：ASR 已完整完成，账本已记录成功，文字稿确实存在、非空且字数与记录一致。

- 文字稿与笔记继续保留，不随视频删除。
- 清理不等待笔记生成成功；已有可靠文字稿，即使笔记生成失败，视频仍可清理，后续用文字稿续跑。
- ASR 失败、文字稿为空或缺失时，视频保留并继续计入空间上限。
- 中断遗留的、已经符合条件的视频，下次正常启动会补清理。
- 视频清理后可能留下空的作品 ID 文件夹，这是正常现象。

因此，**视频目录为空不代表没有处理成功**，最终应看笔记和账本。外接硬盘的归档、文字备份、挂载检查全部停用，无需接盘；当前程序也不会把这些产物另存一份到外接盘。

## 3. 账本怎么查看、怎么看懂

账本是 SQLite 数据库，不是可直接阅读的文档。日常使用已有查询命令即可，不需要另装数据库软件。

### 看全局：处理进度与今日额度

```sh
node scripts/ledger.mjs stats
node run.mjs --status
```

第一条是易读的总览。第二条输出详细 JSON，主要看：

| 字段 | 含义 |
|---|---|
| `baseline` | 已建立的扫描基线及参照，不是待下载的 100 条 |
| `pending` | 当前还能自动继续处理的待办总量，涵盖下载、转写、笔记阶段 |
| `usedToday` | 按本机日期计算，今天已经占用处理额度的不同作品数 |
| `policy` | 当前生效的处理限制 |

`pending` 不含已完成、主动跳过或已达到失败重试上限的条目；所以它为 0 时，仍可通过账本检查有无 `failed`。查看状态最好在一轮结束后；`--status` 和 `--dry-run` 也使用运行锁，正在处理时可能提示已有任务运行。

### 看明细：哪些在等、哪些完成、哪些失败

下列命令分别列出对应状态最多 20 条，选择需要的执行：

```sh
node scripts/ledger.mjs list pending 20
node scripts/ledger.mjs list downloaded 20
node scripts/ledger.mjs list transcribed 20
node scripts/ledger.mjs list extracted 20
node scripts/ledger.mjs list failed 20
```

| 状态 | 意思 |
|---|---|
| `pending` | 已记账，等待下载 |
| `downloaded` | 视频已下载，等待转写 |
| `transcribed` | 文字稿已完成，等待生成笔记 |
| `extracted` | 笔记已生成 |
| `skipped` | 按规则跳过；具体看 `skip_reason` |
| `failed` | 重试达到上限，停止自动重试，需要排查 |

**现有 100 条 `skipped / baseline` 是正常的历史基线，不是 100 条失败。** 其他跳过原因可能是图集、超过 10 分钟等。一次失败未达到上限时，条目可能仍留在原阶段，应结合运行日志和单条的 `last_error` 判断。

查看某条的完整记录：

```sh
node scripts/ledger.mjs show 作品ID
```

把 `作品ID` 替换成上面列表中的数字 ID。重点查看 `status`、`last_error`、`attempts`、`text_path`、`note_path`、`media_deleted` 和 `skip_reason`。其中 `media_deleted=1` 表示视频已经清理；即使 `media_path` 还保留旧路径，也不表示该文件仍存在。

## 4. 每次运行结束后看什么

先看终端最后一行，例如：

```text
结束：处理 2，成稿 2，待办 0，正常收尾
```

上面是输出格式示例，不是本次实际运行结果。`处理` 是本轮进入处理流程的数量，不能直接等同于成功数量；判断结果还要看成稿、跳过、失败和暂停原因。

需要追查时，打开 `/Users/enna/.dustoff/runs`，按修改时间找到对应的一轮目录：

- **`run.log`**：按顺序记录过程和错误，先读这个。
- **`result.json`**：结构化结果，便于核对下表数字。

| 字段 | 看什么 |
|---|---|
| `scanned` / `added` | 扫描了多少条元数据、加入了多少新增待办；不等于下载数量 |
| `processed` / `text` / `notes` | 本轮处理数量、完成转写数量、成稿数量 |
| `skipped` / `failures` | 本轮跳过数量、失败条目及原因 |
| `paused` | 为什么提前暂停；正常无暂停时为 `null` |
| `pending` / `usedToday` | 收尾时剩余待办、今日已用额度 |
| `cleanup` | 收尾清理数量、字节数及未能清理情况 |
| `transcriptLayouts` | 各篇转写稿的段落数和完整性记录；`mode: original` 表示排版回退，原因见 `reason`，原稿仍完整 |

文件夹名称里的时间使用 UTC，与本机时间有时差；优先按修改时间和日志内容找对应的一轮。日志按当前配置保留 30 天，并有每个运行入口最多 100 份的数量限制，不是永久历史；长期处理状态看账本。

## 5. 手动运行时仍然生效的限制

| 限制 | 实际行为 |
|---|---|
| 每日最多 50 条 | 当日本机日期内累计计算；多次手动运行与定时运行共用，不是每点一次就重新给 50 条 |
| 单条最多 10 分钟 | 视频时长超过 600 秒跳过；这是视频时长限制，不是要求整条流水线必须在 10 分钟完成 |
| 扫描窗口 100 条 | 用于确认新增边界；未确认时继续分页，不是固定下载 100 条 |
| 本地媒体上限 1 GiB | 视频缓存和临时媒体一起计算；不包含文字、笔记、登录资料等所有项目数据 |
| 本机空闲低于 10 GiB | 暂停新增下载，不自动突破门槛 |
| 同一时间只跑一轮 | 重复启动会被运行锁拦住；等上一轮结束再运行 |

每日额度统计不同作品；同一作品在当天继续后续阶段不会再次占一个新名额。进入处理后失败也可能已经占用额度，因此“今日已用”不一定等于成功笔记数。

定时与手动运行使用同一份账本、锁和每日额度，已完成的作品不会重复处理。定时碰到手动批次正在运行会被锁拦住，本次不会并行处理；可在手动批次结束后再次手动运行，或等待下一次定时。

## 6. 遇到常见情况怎么办

### 想继续已有待办，暂时不扫描收藏列表

```sh
node run.mjs --no-scan --limit 2
```

从已有待办继续下载、转写或生成笔记。视频地址过期时仍可能联网刷新单条元数据，因此这不是离线模式。

### 想停止当前一轮

在运行它的终端按 **Ctrl+C**。已记账的阶段保留，下次按账本继续；中断可能留下视频或临时文件，由下次正常启动处理。无需清空账本、重建基线。

### 提示登录过期或需要扫码

等当前运行退出后执行：

```sh
node scripts/login.mjs
```

完成 Chrome 中的扫码登录，再运行 `node run.mjs`。登录过期时也可能出现 `/Users/enna/.dustoff/NEEDS_LOGIN` 提示文件。

### 某一条达到失败上限

先用 `show` 和 `run.log` 看具体原因，解决后只重试这一条：

```sh
node run.mjs --retry 作品ID --no-scan --limit 1
```

把 `作品ID` 换成真实数字 ID。程序根据已有视频、文字稿恢复到合适阶段，不需要把整批重新下载。此命令不能把基线历史条目、已完成条目或规则跳过的超长视频、图集当作失败待办重做，也不会重置今日总额度。

### 空间不足、额度已满，或目录一直有视频

先看本轮 `paused`、`failures` 和对应作品状态。需要查看实际磁盘空间时：

```sh
df -h /Users/enna/.dustoff
du -sh /Users/enna/.dustoff/media /Users/enna/.dustoff/tmp-media
```

第一条看所在磁盘的可用空间；第二条分别看两类媒体占用。账本 `stats` 中的素材占用来自记录，不包含所有临时文件，不能代替实际磁盘检查。

- 今日额度满：剩余待办保留，下一天再运行。
- 空闲低于 10 GiB：需要先释放本机空间；再次点击不会绕过门槛。
- 媒体达到 1 GiB：检查是否有 ASR 失败、空文字稿或清理失败的视频。保留的视频有具体原因，先排查，避免把尚无文字稿的素材直接删除。
- 笔记缺少画面里的链接、代码或其他信息：当前 OCR 尚未接入，需回看原作品核对；`needs_ocr` 标记不代表补充内容已经完成。
