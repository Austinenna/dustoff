# dustoff

给吃灰的收藏夹掸掸灰：读取抖音、B站的新收藏和 X 书签，保存视频和图集，或通过字幕、语音转写、原帖整理为知识笔记。

## 环境定位

- **Linux 服务器：生产环境。** 正式账本、媒体、笔记、账号连接与自动整理在服务器运行，通过 HTTPS 密码认证的网页访问。
- **本机：开发环境。** 修改代码、运行隔离测试、维护文档和提交。提交或推送不自动部署生产。
- 本机沿用 `~/.dustoff` 中的开发样例。`打开控制台.command` 启动本地控制台；生产地址保存在私有运维文档中。

## 核心流程

扫描收藏 → SQLite 基线与待办 → 判断用途 → 保存视频/图集，或转写并生成 Markdown 笔记。

三个来源同一个定时、同一轮运行，扫描状态、登录、每日额度和风控暂停各自独立：

- **抖音**：无界面 Chrome 截获收藏列表；首次只登记最近 100 条为历史基线。
- **B站**（默认关闭，`DUST_BILI_ENABLED=1` 开启）：带登录 Cookie 直连收藏夹接口，只处理起始日期之后的收藏，存量不登记。默认跟踪全部自建收藏夹，可排除或给收藏夹指定用途。新收藏默认进入「待确认」，由用户选择用途和画质（默认最高 1080p）。笔记用途优先使用字幕（人工字幕优先于 AI 字幕），没有字幕时只下载音频走转写；视频用途保存第 1 P。

- **X 书签**（默认关闭，`DUST_X_ENABLED=1` 开启）：走 X 官方接口（按调用计费），在控制台「连接 X」完成只读 OAuth 授权，Client ID / Secret 只写在 `dustoff.conf`。首次读入全部书签（官方接口最多返回最近 800 条），之后只读顶部新增。每条帖子都保存原帖（正文、X 长文全文、引用推文、链接、图片）；正文达到 `DUST_X_NOTE_MIN_CHARS`（默认 280 字）的另外整理成笔记，笔记模型因内容审核拒绝时只保存原帖；带视频的推文由模型判断保存视频或转写成笔记。代码在 `scripts/sources/x/`，预览：`node scripts/sources/x/index.mjs --dry-run`。

运行期间在控制台选择用途、画质或放弃处理，会先记下，本轮结束（或控制台发现空闲）时执行。代码在 `scripts/sources/bilibili/`。

### 知识库索引

`knowledge.mjs` 是笔记之后的第四段：读每篇笔记的提炼正文，让模型抽出它讲到的概念（产品、项目、方法、人物、机构、话题）、概念之间的 5 种固定关系和所属大类，存进 `$DUST_HOME/knowledge.sqlite`。全部抽完后按大类做一次归并：同一个东西的不同写法直接合并，模型拿不准的记成待确认建议。

- 只读笔记和账本，只写 `knowledge.sqlite`，不改笔记的「分类」「标签」。这个文件可以随时删掉重建，做过的合并会重放。
- 大类是固定的 20 个，定义在 `scripts/knowledge-extract.mjs`。
- 目前需要手动运行，尚未接入每日定时：`node knowledge.mjs`（`--dry-run` 只看待抽取篇数，`--report` 看统计，其余参数见文件开头）。

## 控制台

网页控制台按“收进来 → 做决定 → 整理 → 读和用”组织：

- **今日**：本周新笔记、等你决定的条目、四段流水线状态、需要留意的问题，以及“重温”一篇旧收藏。
- **笔记下载视频**：已整理的笔记可在收藏详情点「下载高清视频」，下一轮按保存视频的规格下载，笔记继续留在知识库，成功后清掉低清素材。下载不成时回到知识笔记并写明原因，可以再试或取消。
- **收件箱**：只放需要你选用途的收藏，逐条处理（键盘 N 笔记、V 视频、D 放弃、J/K 切换）。排队自动处理的条目在流水线页。
  待确认的视频在每轮运行收尾按“保存视频”的规格预下载到 `saved-media/.review/`（与视频收藏共用空间上限，占当天额度；超过 30 分钟的不预下载，失败的 24 小时后再试），收件箱里可以先看再决定：选“保存视频”直接移进收藏并标为已保存；选“知识笔记”原地转写，整理完按清理规则删除（B站笔记仍优先用字幕，不复用预下载；B站换了画质也会重新下载）；放弃或删除记录时删掉暂存文件。
- **知识库**：按阅读状态、主题、标签、来源筛选；打开即标为已读；阅读区可收起列表（`[`、J/K 翻篇）。
- **媒体库**：视频、图集、X 原帖。
- **素材箱**：从笔记、摘录（阅读时选中一段）、视频、图集、X 原帖里挑出要用的内容，按选题归拢，状态分待用、在用、已用。收的时候按标签和分类与各选题已有素材的重合程度给出建议，不调用模型。
- **收藏记录**、**流水线**（运行、队列、来源登录、自动安排、运行记录）、**健康**（退出码、失败原因、按作品 ID 查历史、每日产出）、**设置**（含对外访问令牌）。

Linux 使用 systemd 用户服务和 timer；macOS 开发兼容 launchd，开发默认关闭自动安排。

已读记录、选题、素材和访问令牌存放在数据目录的 `library.sqlite`，与收藏账本分开，控制台直接读写，不经过流水线锁。成本由 AI 网关按单价估算：用途判断、转写、笔记三处调用分别带 `X-Gateway-Category`（router / asr / note）和 `X-Gateway-Task-ID`（作品 ID），控制台从网关 `/v1/usage` 读本月、今天和单条作品的费用，未定价、用量未知的次数单独列出。网关返回 402（项目月预算用完）时整轮暂停、不重试，并显示网关的说明。

### 素材箱对外接口

外部服务通过 `<控制台地址>/api/v1/` 读取素材箱，只用 `Authorization: Bearer <令牌>` 认证（不需要控制台密码），令牌在「设置 → 外部访问」创建，明文只显示一次，库里只存哈希，可随时吊销。只读令牌能读，读写令牌还能回写“已用”。每个令牌每分钟最多 120 次请求，调用记录在 `console/api-access.jsonl`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/topics` | 选题列表 |
| GET | `/materials?topic=&status=&kind=&limit=` | 素材列表，`topic=none` 为未归类 |
| GET | `/materials?since=<秒>&after=<id>` | 增量拉取，按修改时间升序；返回 `next` 作为下次的游标 |
| GET | `/materials/{id}` | 单条素材：摘录、备注、来源链接、笔记全文、媒体清单 |
| GET | `/materials/{id}/media/{n}` | 下载视频（n=0）或图集第 n 张 |
| POST | `/materials/{id}/usage` | 标记已用：`{channel, title, url}`，需要读写令牌 |

## 依赖

- Node.js 24 系列：内置 SQLite、Fetch、WebSocket；无 npm 运行依赖。
- Chrome：抖音登录和收藏采集。
- FFmpeg / ffprobe、`file`：媒体验证、音频处理及播放预览。
- Python 3：迁移工具和迁移测试。
- Linux 远程有界面登录另需 Xvfb 与中文字体；公网由 HTTPS 反向代理保护，Node 只监听回环。

## 本机开发

沿用 `~/.dustoff`，从笔记、视频、图集各 10 条样例开始，后续可自行下载和修改，不限制数量，不再初始化新的开发目录。真实样例不加入源码仓库。

双击 `打开控制台.command`，或在终端运行：

```sh
DUST_HOME="$HOME/.dustoff" \
DUST_PUBLIC_URL= DUST_SERVER_MODE=0 DUST_REMOTE_LOGIN=0 \
DUST_AUTO_SCHEDULE=0 DUST_NOTIFY=0 \
node console.mjs --port 47832
```

访问 `http://127.0.0.1:47832/`。本机配置 `dustoff.conf` 中持久设置 `DUST_AUTO_SCHEDULE=0` 和 `DUST_CONSOLE_PORT=47832`，普通启动不会自动开启定时，手动处理仍可使用。笔记存放于数据目录内的 `notes/`，开发与生产各自独立。

## 验证

```sh
DUST_NOTIFY=0 node --test tests/*.test.mjs
python3 tests/migrate-data.test.py
git diff --check
```

测试使用临时目录和 `tests/fixtures/` 中的虚构固定文本，不依赖私有文档或生产数据。系统集成用例按平台或显式开关执行。不要在测试命令前加 `DUST_AUTO_SCHEDULE=0`：环境变量会覆盖定时相关用例自己的配置。

B站接口可用本机账号只读预览（不写账本、不推进扫描位置）：

```sh
node scripts/sources/bilibili/index.mjs --dry-run
```

## 排查

每轮运行的日志在数据目录的 `runs/<时间>-<进程>-run/run.log`（开头记有代码版本），结果在同目录 `result.json`。另有一份跨轮次的摘要 `runs/history.jsonl`（最近 2000 轮），记下版本、退出码、各项计数，以及每条失败的作品、平台、类型和原因：

```sh
node scripts/run-history.mjs              # 最近 20 轮
node scripts/run-history.mjs --failures   # 只看有失败、暂停或扫描受阻的轮次
node scripts/run-history.mjs --id <作品ID>  # 某条作品在哪几轮失败、原因
```

退出码：0 完成；1 整轮异常；2 跑完但有条目失败或扫描受阻；5 暂停（额度、空间、平台风控）。定时服务把 2、5 视为正常结束，systemd 显示 failed 只代表真正的异常。
