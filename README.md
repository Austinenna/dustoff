# dustoff

**v0.5** · 给吃灰的收藏夹掸掸灰。

自动把收藏夹里的视频抓下来，为后续整理成个人知识库做准备。目前实现了**抖音**，架构上留了扩展其他平台的余地。

> 名字取自英文 *dust off* —— 重新拾起久置之物。

## 版本说明

**0.5 — 采集与提取两段都已打通。** 收藏夹 → mp4 → 文字稿 → 到期删 mp4，两条命令跑完整链路，已实测。

**还不到 1.0**，因为最后一段还没开工——把文字稿提炼成能检索的知识笔记。在那之前，这个工具把视频从「刷不到」变成了「一堆文字稿躺在硬盘里」。

下一步是 `1.0` 第三段提炼笔记，之后才是 `0.6` 接 launchd 定时（先接定时只会每天自动囤一批没人消费的文字稿）。完整路线见 [`docs/架构.md`](docs/架构.md)。

## 下一步

按依赖顺序。前两项是人工操作，其余是待开发。

### 需要你做的

- [ ] **跑一次全量初始化**。插上外接盘，`node sync.mjs --init`。以约 5800 条的收藏夹为例、10 分钟时长上限生效时约 **16 GB / 35 分钟**（不设上限则 29 GB / 59 分钟）。跑之前确认 `ls /Volumes/` 里能看到你的盘。
- [ ] **接 launchd 定时**。日常增量约 28 秒，建议每天一次。要处理退出码 `4`（登录失效）——否则会静默停摆好几周。
- [ ] **在 `sessionid` 到期前重新扫码**。实测有效期约两个月，守卫会提前 7 天弹通知并写 `~/.dustoff/NEEDS_LOGIN`。
- [ ] **过一两周看一眼 `~/.dustoff/state/session.json`**。若 `history[]` 里的 `expires_at` 在自动往后推、`auto_renewing` 变成 `true`，说明日常访问本身就在续期，那整套登录告警可以撤掉。

### 待开发

- [ ] **扫描层增量**。目前每次都扫固定条数，靠账本筛掉已处理的——结果正确但每次白扫约 185 条已知条目（21 秒）。改成「连续撞到 N 条已知就停」可压到 2-3 秒。机制已验证：收藏列表按收藏时间倒序，新增永远是顶部连续一块（实测 3 天新增 46 条，占据位置 0–45）。
- [ ] **图集处理**。约 829 条（14~33%），`listcollection` 已返回 `images[]` 数组，只是没接。
- [ ] **第三段：提炼笔记 → 知识库**。ASR 已完成，缺的是从文字稿到笔记这一步。开工前要先定「哪些条目配写笔记」——实测收藏夹里一半以上是段子和广告。见下方「已定的技术选型」。
- [ ] **OCR 增强**。当前只用 ASR，拿不到屏幕上的文字。完整方案见 [`docs/待办-OCR增强.md`](docs/待办-OCR增强.md)。

## 快速开始

```bash
# ① 一次性：扫码登录（弹出 Chrome，用抖音 App 扫码）
node scripts/login.mjs

# ② 一次性：装配置
cp dustoff.conf.example ~/.dustoff/dustoff.conf   # 按需修改

# ③ 首次初始化：全量拉到外接盘（约 59 分钟）
node sync.mjs --init

# ④ 日常：增量，落本机（约 28 秒）
node sync.mjs
```

**两种模式不需要改配置。** 配置文件里两套值都写好，命令行选用哪套 —— 带 `_INIT` 后缀的键只在 `--init` 时生效：

```bash
DUST_MEDIA=~/.dustoff/media                  # 日常
DUST_MEDIA_INIT=/Volumes/YourDisk/dustoff-media   # --init
DUST_SCAN_COUNT=200                          # 日常
DUST_SCAN_COUNT_INIT=99999                   # --init，扫到底
```

### sync.mjs 的其他用法

```bash
node sync.mjs --dry-run          # 只报计划，不下载
node sync.mjs --list             # 列出最近的运行记录
node sync.mjs --resume <run-id>  # 重试某次的下载，不重新扫描
```

`--resume` 是为初始化准备的：全量要跑近一小时，万一中途断了，拿那次存下的 `coll.json` 直接续下载即可，不用重扫（前提是 CDN 地址还在有效期内）。

### 退出码

定时任务据此判断该不该告警。

| 码 | 含义 |
|---|---|
| `0` | 成功 |
| `1` | 出错 |
| `3` | 已有实例在跑，本次直接退出（不排队） |
| `4` | **登录态失效，需要重新扫码** |
| `5` | 外接盘未挂载（仅 `--init`） |

### 也可以绕过入口直接调

```bash
node scripts/get_collection.mjs 200 | node scripts/download.mjs - 3
```

调试单步时方便，但没有加锁、日志和运行记录。

## 脚本一览

**两个入口**（根目录）。它们是平级的独立阶段，互不调用，只通过账本对话——
所以入口放在根目录，跟被调用的零件分开。

| 入口 | 作用 |
|---|---|
| `sync.mjs` | ① 采集：扫收藏夹 → 下载 → 写账本 |
| `extract.mjs` | ② 提取：清理过期 mp4 → 转写成文字 → 写账本 |
| `notes.mjs` | ③ 提炼：读转写稿 → LLM 写笔记 → 写账本 |

以下都在 `scripts/` 下，是被入口调用的零件（或独立的小工具），不是入口。

**批量路径**（收藏夹 → 下载）

| 脚本 | 作用 |
|---|---|
| `login.mjs` | 有头 Chrome 扫码登录，登录态存进固定 profile。一次性 |
| `get_collection.mjs` | headless Chrome 复用登录态，CDP 截收藏夹接口，输出含播放地址的 JSON |
| `download.mjs` | 吃上一步的 JSON，并发下载最低码率档，校验后落盘 |

**库**（不单独运行）

| 脚本 | 作用 |
|---|---|
| `lib.mjs` | 挑码率档（要求带音轨）、解析 CDN 地址时效、判定图集 |
| `session_guard.mjs` | 按自然日节流检查登录态剩余天数，预警 |
| `stage.mjs` | 阶段骨架：PID 锁、日志落盘、运行记录、通知、退出码。两个入口共用 |
| `config.mjs` | 配置解析（命令行 > 环境变量 > 配置文件 > 默认） |
| `ledger.mjs` | 账本。两段之间唯一的共享状态，也可当 CLI 用 |
| `timeline.mjs` | 把转写稿和逐词时间戳合成「分句 + 时间戳」视图 |

**单条链接路径**（与批量无关，给「随手丢一个链接」用）

| 脚本 | 作用 |
|---|---|
| `get_meta.mjs` | 单条链接 → 播放地址 |
| `fetch.mjs` | 单条链接 → 下载 → 抽音频 → whisper 转写 |

## 实现要点

**不逆向签名，让真浏览器替我们签名。** 抖音的 web 接口需要 `a_bogus` 等签名参数，自己实现很脆弱（GitHub 上 15k star 的同类项目 README 里自己写着「加密参数算法已过期失效」）。本项目启动系统 Chrome，用 CDP 截获页面自己发出的接口响应 —— 抖音要打掉这条路，得先打掉自己的网页版。

**批量流程只启动一次浏览器。** 收藏夹接口 `listcollection` 的响应里已经带了 `play_addr` 和 12 档 `bit_rate`，所以扫描时一并提取，下载阶段全程 `curl`，不再逐条起 Chrome（那样 5000 条要多花约 8 小时）。

**下低码率档，但必须带音轨。** 只要内容不要原件，所以不下默认的 `play_addr`。但**不能无脑取最低档**——实测 58% 的视频，最低那几档是纯视频没有音轨，而后半段靠 ASR 提取内容，没音轨等于白下。

规律是同一个 `gear_name` 会在 `bit_rate` 里出现两次，高码率那个比低码率的多约 55 kbps，那 55 kbps 就是音频轨。但这规律不通用（有些视频档位互不重名且最低档就带音频），而 `audio_bitrate` 字段两类视频上都可能缺失。所以策略是：**按规律优先猜带音轨的档 → 下载后 `ffprobe` 验证 → 验不过回落 `play_addr`**（网页播放器用的地址，必然有音轨）。

实测 31 条全部拿到音轨，回落一次都没触发，体积只比「无脑取最低档」多 18%。

**CDN 地址有时效。** 地址路径第二段是十六进制的过期时间戳，实测 3~24 小时不等。下载前会先判断，过期直接跳过并提示重扫，不做注定 403 的无用请求。因此**扫描与下载不能隔太久**。

**超长视频不下。** 短视频的时长极度长尾：实测样本中位 58 秒，最长的一条却有 841 分钟。超长的多是合集、解说、全片，做知识笔记价值低却吃掉大量体积。默认拦下超过 10 分钟的——实测只影响 4.6% 的条目，却省约 12.6 GB。被拦下的不丢弃，会计入汇总并列出最长的几条，想要的可以单独捞。

**下载四重校验。** CDN 失败时常返回 HTTP 200 的错误页，只看状态码会把 HTML 当 mp4 静默写入。所以要求：`curl --fail` + 文件 > 10 KB + `file --mime-type` 是 `video/*` + `ffprobe` 确认有音轨，四关全过才算成功，否则换下一个地址或回落 `play_addr`。

## 已定的技术选型

后半段还没开工，但选型已经用实测数据定下来了，不必重新论证。

**转文字用云端 ASR，不用本地 whisper。** 同一条视频、真值取自画面硬字幕，云端 ASR 错 1/8，本地 `whisper base` **错 8/8**（Claude Code→Cloud Code、图表→图标、时序图→实序图、重绘→重惠…）。**whisper 已淘汰**，不留作兜底。

**模型是 `qwen-audio-3.0-asr-flash`**，走同步 `multimodal-generation` 端点，音频 base64 内联。同价的 `qwen3-asr-flash` 也支持，改 `DUST_ASR_MODEL` 即可切换——两族的请求与返回差异隔在 `extract.mjs` 的 `DIALECTS` 里。选型全过程见 [`docs/ASR选型-2026-09-02.md`](docs/ASR选型-2026-09-02.md)。

**热词不只提准确率，也管输出格式。** `~/.dustoff/asr-context.txt` 里的词会被优先识别：不给热词认成 `cloud code`，给了就是 `Claude Code`；且**在表里的缩写输出干净（`SVG`），不在表里的会被拆成字母（`S V G`）**。想到新词随时加。

**单价 ¥0.00022/秒**（华北2，已核实；≈¥0.79/小时）。按收藏夹真实分布算：日常增量 **¥0.28/天 ≈ ¥8.4/月**，存量全量约 **¥109** 一次性。`qwen-audio-3.0` 另有 10 小时免费额度（到 2026/10/27），够用 28 天日常增量。

**300 秒是硬上限**，超了自动按静音中点切片（占 9%，实测接缝不劈词）。异步端点（`fun-asr`）不限时长但故障面从 1 处涨到 8 处，这段代码跑在凌晨无人值守，不划算。

**OCR 暂缓，但迟早要加回来。** ASR 拿不到屏幕上的文字——实测一条屏幕录制视频，ASR 171 字 vs OCR 9396 字。完整依据与实现方案见 [`docs/待办-OCR增强.md`](docs/待办-OCR增强.md)。

**分类分四类**：AI技术 / 游戏攻略 / 生活方式 / 其他。按样本关键词粗分约为 28% / 6% / 11% / 55%——「其他」占比过高说明规则太糙，实际应交给 AI 判断。

**时效性按条打标，不按类目一刀切。** 同样是游戏攻略，网游会过期、单机不会。建议四档：`none`（菜谱/摄影技巧/单机攻略/原理方法论）、`slow`（1-3 年，框架用法）、`fast`（6-12 月，模型对比/API 用法）、`event`（时点绑定，网游版本/活动/新闻）。判定放在元数据阶段，零转写成本。

**暂不上 RAG / 向量库。** 首轮 AI 类约 1300 条 markdown，`grep` 完全够用；知识库最常见的查询是「我记得存过一个讲 XX 的」——这是关键词检索，向量库反而不准。等 `grep` 真不够用了再上。

**存量处理的量级**（以约 5800 条的样本为例）：约 5000 视频 + 800 图集，视频总时长约 244 小时。OCR 按实测 3.0× 实时算，全量约 81 小时；只做 AI 类 + 2025 年起约 21.6 小时，并发 4 路可压到约 7 小时。

## 已知限制

- **图集不下载**。约占收藏的 14~33%，能正确识别并跳过，但没有处理路径。
- **超过 10 分钟的视频不下载**（可配置）。拦下的会列在汇总里，需要时用 `node scripts/fetch.mjs '<链接>'` 单独下，或 `DUST_MAX_DURATION_MIN=0` 临时放开。
- **无扫描层增量**。每次都扫固定条数，靠下载层的文件缓存去重 —— 结果正确，但每次白扫已知条目。
- **登录态约两个月过期**，需要重新扫码。守卫会提前 7 天预警。
- **依赖抖音网页版结构**。收藏页的滚动容器、接口路径若变更需要跟进。

**快照与变更记录为什么分开：** 快照要能直接回答「现在是什么样」——
混进历史就得一边读一边判断哪句还作数。变更记录则要回答「为什么是这样」，
那些被推翻的方案和当时的理由，正是防止兜回老路的东西，删不得。

```
dustoff/
├── sync.mjs                 ① 采集入口：扫收藏夹 → 下载 → 写账本
├── extract.mjs              ② 提取入口：读账本 → 转写 → 清理 mp4
├── scripts/                 零件，不单独当入口用。见上方「脚本一览」
├── docs/                    架构、选型依据、待办（见下方「文档」）
├── dustoff.conf.example     配置模板，复制到 ~/.dustoff/ 后修改
├── README.md
└── .gitignore               挡住所有运行时产物，防止误入库
```

### ② 运行数据 · `~/.dustoff/`

不进 git。**丢了重跑一遍就有**（登录态是唯一例外）。

```
~/.dustoff/
├── dustoff.conf             你的实际配置。不入库，因为含本机路径
├── chrome-profile/          登录态。⚠️ 唯一丢了不能自动恢复的——要重新扫码
├── state/session.json       登录守卫记录：到期时间、每日检查历史
├── runs/                    每次运行的现场，留 30 天
│   └── <时间戳>/            coll.json（扫到什么）· result.json（下载结果）· run.log
├── index.sqlite             账本：每条的状态、产物位置、AI 判断结果
├── media/                   视频。唯一会长大的目录，约 72 MB/天
└── NEEDS_LOGIN              登录告警标记。正常时不存在，出问题才出现
```

`runs/` 留着有三个用处：下载失败时可在地址有效期内直接重试而不用重扫；凌晨跑的任务出问题时这是唯一的现场；攒久了能看出哪个 CDN 老失败。

⚠️ `runs/` 里的 `coll.json` **含带签名的 CDN 地址**，有效期内拿到就能下载你的收藏。所以它留本机，不跟视频一起进移动硬盘。

### ③ 资产 · 某个 Obsidian vault

不进 git，**必须备份**。丢了就真丢了 —— 原视频可能已被作者删除，AI 每次提炼的结果也不同，重跑回不来同一篇。

```
<vault>/抖音收藏/
└── YYYY-MM-DD-<主题>.md     最终笔记（后半段产出，尚未实现）
```

**刻意放在 dustoff 之外。** 工具会被换掉、重写、废弃，知识不该跟着走；而且将来扩展其他平台时，知识库该是各来源的汇聚点，不是某个采集器的子目录。位置由 `DUST_NOTES` 配置。

### 关于移动硬盘

`media/` 是唯一需要考虑外置的目录。两种用法：

| 场景 | 配置 | 量级 |
|---|---|---|
| 日常增量 | 留默认 `~/.dustoff/media` | 约 61 MB/天，转写后 7 天删，稳态约 430 MB |
| 首次初始化 | `DUST_MEDIA=/Volumes/<盘名>/dustoff-media` | 全量可达数十 GB，本机多半装不下 |

`/Volumes/<盘名>` 是硬盘的**挂载点** —— macOS 插盘后自动创建，拔盘即消失。所以脚本用「父目录是否存在」来判断硬盘在不在：存在就自动建下面的 `dustoff-media/`，不存在就**报错退出**。绝不静默落回本机 —— 那会瞬间填爆系统盘。
